# Payload roles feasibility gates

This page records what the executable probes for `@codlume/payload-roles` observed. Each gate ran as a script against a real Payload install, in throwaway fixtures outside the workspace. Read it before you build lifecycle enforcement or the admin matrix. The full reports, probe scripts and raw logs stayed in the implementation worktree's `proof/gates/` folder. That folder is not committed.

Versions. Gates ran on Payload 3.90.0. The GraphQL autosave check ran on 3.90.1. The package pins 3.90.1 and declares `payload >=3.90.1 <4`. The 3.90.1 change is limited to relationship `where` handling ([#18212](https://github.com/payloadcms/payload/issues/18212)). It does not touch the gated paths, but that conclusion comes from reading the diff and was not run. A version research pass compared the cited source files at v3.90.0 and v3.93.0. Only F-29 (draft reads apply the read `Where` to the latest version since 3.91.0) changed between them. Gates were not rerun on 3.93.0.

Adapters. SQLite is the default for every gate. G2, G9, G11, G14 and G20 also ran on Postgres (embedded-postgres), a Mongo replica set, and standalone Mongo. No gate claims cross-adapter behavior from SQLite alone.

Verdicts use four values. VERIFIED means the observed output met the pass condition. DISPROVED means observed output contradicted the planned mechanism. INCONCLUSIVE means the probe could not observe the answer. DEFERRED means the capability is optional in v1.

## Security gates

| Gate                          | Verdict              | What was observed                                                                                                                                                                                                                                                                                                                                                                          | What the design does now                                                                                                                                                                                                                                                            |
| ----------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1 Intent survives nesting    | DISPROVED            | A `WeakMap<req>` Intent stack leaks. When app code catches a failing nested `payload.update({overrideAccess: true, req})`, the nested entry is never popped, because `afterError` runs only from `utilities/routeError.js`. The outer user request then reads the trusted entry and returns 200. `restoreVersion` also hands hooks a Proxy of `req`, and globals have no `afterOperation`. | Lifecycle carries Intent with `AsyncLocalStorage.enterWith` at the top of `beforeOperation`. That design passed all 18 scenarios, including nested failures, GraphQL, the restore Proxy and concurrent updates on one `req`. Core guards run in `beforeOperation` and use no stack. |
| G2 Main-row read before write | VERIFIED             | `payload.db.findOne` inside `beforeChange` returns the pre-write `_status` for P and PD on all four adapters. Concurrent writes can race on SQLite, standalone Mongo, and Postgres with a plain read. Postgres `SELECT ... FOR UPDATE` closed the race. A Mongo replica set aborts the stale writer.                                                                                       | Lifecycle uses the main-row read. Concurrency limits are documented, not claimed atomic.                                                                                                                                                                                            |
| G3 Implicit unpublish         | VERIFIED             | A non-draft PATCH without `_status` on PD flips the main row to draft. Inside `beforeChange`, both `originalDoc._status` and `data._status` are `draft`, and only the main-row read still says `published`.                                                                                                                                                                                | Lifecycle requires `unpublish` for it (Q5).                                                                                                                                                                                                                                         |
| G4 Global restore             | VERIFIED             | Global restore runs `beforeOperation` only. A hook that loads the version and the main global blocked unpublish-by-restore over REST (403) and GraphQL. The Local API does not forward `draft`.                                                                                                                                                                                            | Lifecycle decides global restore in `beforeOperation`.                                                                                                                                                                                                                              |
| G7 Classifier is last         | DISPROVED as stated  | 3.90 sorts plugins by `plugin.order`, then array position. Field-level `beforeChange` hooks run after collection hooks and can still rewrite `_status`.                                                                                                                                                                                                                                    | Core sets a high `order` and asserts hook order at startup. Lifecycle computes `writesMain` from raw flags captured in `beforeOperation`.                                                                                                                                           |
| G13 Duplicate status          | VERIFIED             | Duplicate copies `_status: 'published'` unless the request is a draft save. Create access sees `data: {}`, or `{_status: 'draft'}` on the REST default.                                                                                                                                                                                                                                    | Create on a drafts resource requires `publish` unless `data._status === 'draft'`. Lifecycle keeps a create-side `beforeChange` check.                                                                                                                                               |
| G14 First super admin race    | DISPROVED            | A "set `superAdmin` when count is 0" hook made 10 of 10 racers super admins on SQLite and standalone Mongo, and 9 of 10 on Postgres. `registerFirstUser` creates with `overrideAccess: true` and the raw request body.                                                                                                                                                                     | A hidden unique claim column on the user row. The existence check uses `db.findOne`, not `count`. One super admin resulted on every adapter. Guards trust only Local API calls with `overrideAccess: true` and `req.payloadAPI === 'local'`.                                        |
| G18 Upload side effects       | DISPROVED for update | On update, the new file and its sizes are already on disk by `beforeChange`, and the old ones are deleted. On create, nothing reaches disk before `beforeChange`.                                                                                                                                                                                                                          | Core guards and lifecycle denies on upload collections run in `beforeOperation`.                                                                                                                                                                                                    |
| G19 Stock request bodies      | VERIFIED             | Unpublish, Unpublish Many, move to trash and restore from trash send only `_status` and/or `deletedAt`. Restore from trash is a bulk PATCH with `?trash=true`. Extraction is source-derived and the replays were executed.                                                                                                                                                                 | Lifecycle-only roles can work through stock controls.                                                                                                                                                                                                                               |
| G20 Bulk partial failure      | VERIFIED             | Every adapter's default commits the permitted documents and lists the denied one in `errors` (HTTP 400). The drizzle adapters never set `bulkOperationsSingleTransaction`. With that flag on, a Mongo replica set rolls back earlier documents but still reports them as updated.                                                                                                          | Bulk tests assert a partial commit.                                                                                                                                                                                                                                                 |

## Other gates

| Gate                                   | Verdict                  | Observed                                                                                                                                                                                                                                      | Impact                                                                                                               |
| -------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| G5 Access calls and memo               | VERIFIED                 | A memo keyed on the `req.user` object, storing the promise before awaiting it, gives 1 role query per request across 10 request shapes. With no memo, the edit view made 56 queries. Local API callers that reuse one user object need a TTL. | Promise memo with a 5 s TTL. Failures are never cached.                                                              |
| G6 `user.roles` shape                  | VERIFIED                 | REST, API key and admin load the user at depth 2. GraphQL and jobs load it at depth 0. `initReq` also returns a separate, field-filtered `user`.                                                                                              | Normalize to ids, always reload by id, and set `maxDepth: 0` on the field. Admin components resolve from `req.user`. |
| G8 Queue-time scheduling check         | VERIFIED, blocked        | A jobs hook can see and refuse a `schedulePublish` input only with `jobs.runHooks: true`. On 3.90.0 that marks every successful job as failed.                                                                                                | Q12 stays at execution-time enforcement. The queue-time check is deferred.                                           |
| G9 Global `Where` miss                 | VERIFIED                 | A miss on an existing global throws Forbidden on all adapters. Before the global's first save, the miss is ignored and a row is written.                                                                                                      | Role access on globals stays boolean.                                                                                |
| G10 Probe and outcome divergence       | VERIFIED                 | 8 of 56 cases differ, all on PD documents with an app `Where`. In each, the probe hides the button and the server allows the write.                                                                                                           | Documented. Matters for app `Where`s and for M4.                                                                     |
| G11 JSON storage                       | VERIFIED                 | `permissions` is `jsonb` on Postgres. Adding a resource or an action needs no migration. An array-of-rows design needs enum migrations.                                                                                                       | Keep JSON in canonical stored order.                                                                                 |
| G12 Restore from trash                 | VERIFIED                 | `beforeChange` sees `originalDoc.deletedAt` set and `data.deletedAt === null` on every transport.                                                                                                                                             | Lifecycle detects trash changes by value.                                                                            |
| G15 Deleted or revoked scheduling user | VERIFIED                 | The job fails and writes nothing. A job queued with no user runs with `overrideAccess: true`.                                                                                                                                                 | Disclosed as a trusted bypass.                                                                                       |
| G16 Copy to locale                     | VERIFIED                 | On P it writes the main row with `_status: 'published'` under `draft: true`. On PD and N it is a draft save.                                                                                                                                  | Classified as publish.                                                                                               |
| G17 Conditional grants                 | VERIFIED, DEFERRED       | A both-rows check plus an id-aware access function removes false allows. Verified on SQLite only.                                                                                                                                             | M4 is out of scope for v1.                                                                                           |
| GraphQL autosave                       | VERIFIED at schema level | On 3.90.1, collection `update<Slug>` takes `autosave`. Global update takes only `data` and `draft`. There is no unpublish flag and no bulk update.                                                                                            | Do not invent a GraphQL global autosave. Execution is left to the lifecycle transport tests.                         |

## Plan facts corrected at 3.90

- F-3: bulk update access receives `data`. Collection restore access receives `{id, data: {_status}}`. Global restore checks `readVersions`, then `update` with data.
- F-10: global restore now checks `readVersions` and still runs no field hooks.
- F-11: `createGlobal` runs only for a global that has never been saved.
- F-17: the scheduled job stores the user as `{relationTo, value}` and rejects bare-id jobs. Queueing still checks only admin access, and `deleteID` has no ownership check.
- F-19: confirmed by running it. Users load at depth 2 when `auth.depth` is unset.
- F-22: unlock defaults to `defaultUnlockAccess`, not `Boolean(user)`.
- F-27: `req.context` is replaced on every nested Local API call that passes `req`.
- Section 8 bootstrap: replaced as described under G14.
- Section 8 role writes: "deleting can only reduce privileges, so it needs no subset check" is wrong. Shrinking or deleting a stronger user's role lets the editor change that user's credentials next (core review round 2). Core requires the editor to cover the role's current grants on update, restore and delete.

## Upstream defects seen, not filed

- SQLite with `transactionOptions` enabled returned `SQLITE_BUSY` under concurrent writers, and a later rollback undid committed deletes. This reproduced without any plugin hooks.
- Payload's first-register emptiness check is not atomic with the insert.
